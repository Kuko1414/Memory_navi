# Harness 评估：navi demo 的幻觉来源（harness vs 模型能力）

> 目标：验证"用 harness 让 Qwen3-VL-8B 无幻觉完成简单 navi 任务（左走→右转→看图报告）"是否可行，
> 并判定此前观察到的幻觉是 **harness 问题（可治）** 还是 **模型本身能力缺陷（需换模型）**。
> 结论先行：**是 harness 问题。route-B（每子目标全新短上下文 + 代码核验真值）完全无幻觉。**

日期：2026-06-22。模型：`qwen3-vl-8b`（vLLM :8000，FP16）。仿真：Webots break_room，agent0。

---

## 1. 两种编排对照

### A. 单段对话承载整个多步任务（naive）—— 出幻觉
把整个任务一次性交给 Qwen、让它自己在一段对话里跑完并自判完成。实测**第 6 步**就出现幻觉：

- tool_trace：look → scan → move → scan → move(turn) →（第6步**无 tool_call**，纯叙述）。
- 第6步它宣布"我已移动到红色柜子左侧并向右转，现在我看到…红色柜子、沙发…"，但：
  1. **叙述代替指令**：无任何 tool_call，循环当场结束，机器人没动。
  2. **没做到却说做到**：实际只移动 ~0.07m（欠走）；它把 `turn_deg=+90`（左转）当成并报告"右转"——方向选错且报反。
  3. **看图说谎**：全程只在开头 look 过一次，"现在我看到的"其实是开头那张旧帧；真实当前画面已不同。

→ 根因：开放式多步目标 + 让模型自判完成时，模型倾向"感觉差不多了"就用一段合理叙述收尾。
上下文越长越严重，但该倾向一上来就在。

### B. route-B：每子目标全新短上下文 + 代码核验真值 —— 无幻觉
代码把任务拆成原子子目标，每个子目标是一次**全新、窄** `Executor.run()`（系统提示=单步执行版），
代码在子目标之间用 `get_pose`/真实帧核验。同一个 demo 实测如下。

## 2. Phase 1 route-B 实测（逐子目标）

| 子目标 | 调用工具 | 真值核验 | Qwen 报告 | 幻觉？ |
|---|---|---|---|---|

## 3. 判定

- **幻觉 = harness 问题，可治。** 同一模型、同一任务，仅把"一段对话自跑"换成"route-B 每子目标全新短上下文 +
  代码核验"，幻觉从第6步必现变为**零出现**。不是 Qwen3-VL-8B 的能力天花板，**无需换模型**。
- 三种幻觉的对应消除手段（route-B 已隐含，Phase 2 再显式强化）：
  - 叙述代替指令 → 动作子目标 `tool_choice` 强制工具 + 代码控流（不让模型自判完成）。
  - 没做到却说做到 → 动作后代码用 get_pose/scan 核验真值（已生效：本表"真值核验"列即代码所验）。
  - 看图说谎 → 报告类子目标强制先 look，用返回的新帧（SG5 已如此）。

## 4. 前置：运动闭环（Phase 0）使真值核验成立
此前开环按墙钟计时严重欠走（move 0.5m→0.07m、turn 90°→30°，根因 mecanum 麦轮各向异性摩擦+仿真<1×实时）。
改为**闭环读真值位姿**（gps x,y + imu yaw，到目标即停；safety-shm tripped 即停）后：
move 0.5→**0.506m**、turn_left 90→**+90.6°**、turn_right 90→**−90.2°**，safety 实测 0.14m 触发刹停。
（关键 bug：`ws_manager.receive` 超时会 close 连接丢订阅，receive 超时须>位姿周期，已设 0.5s。）

## 5. Phase 2 harness（已实现）
`agent_core/harness.py`：**Qwen 当规划器**（`plan_task` 纯 chat 输出结构化子目标 JSON）→
**代码当执行器**（`execute_step`：move/turn 由代码 `ros.call` 闭环下发并用 `get_pose` 核验真值；
look/report 用一次全新短上下文 run，代码核验本轮确实调了 look）。控制流与动作执行全在确定性代码，
Qwen 只负责分解 + 看图描述 → 从结构上排除"叙述代替指令 / 没做到却说做到"。
- `tool_loop`/`Executor` 已参数化 `tool_choice`，但实测 **vLLM(hermes) 不支持 `tool_choice="required"`**
  （返回空），故不依赖强制工具，改由"代码执行动作 + 代码核验"达到等效确定性。
- 规划器 prompt 自测一版即修好：初版把"去某物左侧区域"简化成只前进，加"忠实保留并落实方向词"后，
  对 demo 任务正确分解为 7 步（look→move→turn_left→move→turn_right→look→report）。
- 执行器 `call_timeout` 30s→120s：闭环 move 在慢仿真里可达数十秒，超过 MCP 默认 30s 会误超时。

## 6. Phase 3 完成标志（达成 ✅）
demo 任务"红色柜子左侧可通行区域→去左侧→右转→报告所见"，Qwen 自分解 7 步，代码逐步执行+核验，
**ALL VERIFIED=True，零幻觉**：

| 步 | 动作 | 真值核验 | 备注 |
|---|---|---|---|
| 1 | look | looked=True | 报告木地板/远处桌+显示器/右侧沙发 |
| 2 | move 1.5 | 实走 0.25m → **safety_stop** | 前方柜子近，安全闭环及时停（合理完成） |
| 3 | turn_left 90 | Δyaw +90.2° | |
| 4 | move 2.0 | 实走 2.003m | 左转后路通，走满 |
| 5 | turn_right 90 | Δyaw −90.2° | |
| 6 | look | looked=True | 左侧红柜/右侧植物+屏 |
| 7 | report | looked=True | "木地板/远处办公桌显示器/左侧红色柜门储物柜/右侧办公桌屏幕/吊灯" |

**第 7 步报告与真实相机帧逐项吻合**（左红柜、前显示器、右屏、吊灯、木地板），无看图说谎。
结论坐实：**harness 让 Qwen3-VL-8B 无幻觉完成简单 navi 任务，无需换模型。**

## 7. 记忆驱动探索实验：从"幻觉"到"不收敛"——同一枚硬币的两面
为检验更难的任务，预置一份**带缺口的语义记忆**（已知红柜/沙发/绿植，**故意不给红柜后方办公区**），
让 Qwen 走一步验一步绕过去补全；并用**真实世界坐标做答案 key 客观打分**（红柜=`cabinet(1)`@(2.62,0.22)，
后方办公区中心≈(3.18,-0.3)，真实内容=办公桌/椅/显示器/键盘/绿植，见 `break_room_ground_truth.json`）。

**结果（客观失败，但极有价值）：** 感知反馈环机制、无幻觉、代码核验、打分法**全部 work**；但
**VLM 自主目标导航不收敛**——两次实测都几乎**原地打转/乱晃**，从没朝办公区走：
- 打分：① 到达 ❌（距目标 3.52m，仍在起点）；② 朝向 ✅（转一圈碰巧朝对）；③ 语义 ❌（报告是起点视角）。

**核心论断（本轮最大收获）：幻觉与不收敛是同一问题的两面——**
- **不加约束**（单段对话自跑整任务）→ 模型自判完成 → **幻觉**（第 6 步：叙述代替指令/没做到说做到/看图说谎）。
- **严格约束**（route-B：每子目标新上下文 + 代码核验，禁止自判完成）→ **无幻觉**，但开放空间推理（"绕到 X 后面"）
  **不收敛**（原地打转）。
- 放任则"编"，管死则"瘫"。正确解是**分层**：**确定性代码做导航**（"去哪/朝哪"，用坐标+闭环 move/turn，已验证准确）
  **+ VLM 只做语义**（"看到了什么"）。这正是 proposal 的角色分工，本实验用客观数据证明了它的必要性。
- 即：VLM 需要"**上级**"（supervisor / 几何导航）下达空间指令，自己不具备可靠的目标导航空间认知。

**下一步（明天）：** 完善 prompt + 强化流程；给 VLM 补"上级"——代码用坐标把车导到目标区，VLM 只 look+描述；
按需增加 skill / function-call 支持（如 `goto(x,y)` 几何导航、`face(object)`）。

## 8. 途中小问题清单（一句话）
- **运动欠走**：mecanum 麦轮各向异性摩擦 + 仿真 <1× 实时 → 开环按墙钟计时只走命令值 15~33% → 改**闭环读真值位姿**解决。
- **断连丢订阅**：`ws_manager.receive` 超时即 `close()` 连接 → receive 超时必须 > 位姿话题周期（gps 10Hz），设 0.5s。
- **误超时**：MCP 客户端 `call_timeout` 30s < 慢仿真里闭环 move 的数十秒 → `Executor` 提到 120s。
- **强制工具不支持**：vLLM(hermes) 的 `tool_choice="required"` 返回空 → 改"代码执行动作 + 代码核验"达到等效确定性。
- **转向符号歧义**：Qwen 把 `turn_deg=+90`(左) 当右转并报反 → 拆成 `turn_left_deg`/`turn_right_deg`。
- **多机器人混淆**：agent0/agent1 都在原点附近，肉眼误判"没动"（其实 agent0 已移 2m）→ 观察需明确区分。
- **规划方向丢失**：规划器初版把"去某物左侧"简化成只前进 → prompt 加"忠实保留并落实方向词"修正。
