# 室内具身智能体：大模型精确记忆 + 小模型高效执行（学术版 v2）

> 本文件是项目的**学术主张（source of truth）**。工程实现（report）与计划书均以本文件的方法论为准。

---

## 一、问题

大模型（Claude / GPT / Gemini）与本地小模型（Qwen3-VL-8B）各有短板：

- **云端大模型**：多模态理解强，但
  - 导航效果不佳（不擅长连续、低延迟的空间控制）；
  - 记忆"存得多、用得少"——读一堆文本只用一点信息，**信息利用率低**；
  - 延迟高（1–3s）。
- **本地小模型 Qwen3-VL-8B**：推理快、本地构建信息灵活，但**缺乏规范和明确 prompt 时会"不知所措"**。
- **多模型"共同决策"是个陷阱**（与工程初版方案的关键分歧）：
  - 让两个模型共同参与同一决策，**任务逻辑容易冲突**；
  - 依赖模型自评置信度来触发"升级到云端"并不可靠——**模型对自己的错误往往无感知（过度自信）**，该升级时不升级；
  - **结论**：不应让两个模型"共同决策 / 仲裁"，而应**各取所长、按职责分工**。

## 二、核心洞见：机器人执行任务不需要全局信息

关键观察——**靠近才能看清**：

- 从远处看一个物体是看不清的；机器人要做的是先**靠近**。
- **快速靠近阶段**（小模型任务）不需要大量信息协助，只要**语义拓扑**就能到达目标区域；
- **靠近之后**（大模型任务）才需要调用该区域的**精确语义信息**做查找与交互。

由此引出我们与 Embodied-RAG 的本质区别：

| | Embodied-RAG | 本工作 |
|---|---|---|
| 记忆形态 | 一份**完整的地图**，供大模型全局思考 | 一本**词典**，按需查条目 |
| 检索方式 | 自顶向下全局检索 | 拓扑导航到位 → 再查局部语义 |
| 信息利用率 | 低（加载全局、用其一隅） | **高**（稀疏、按任务阶段检索） |

> 一句话：**他们提供的是地图，我们提供的是词典。** 执行任务时不必通读整张地图，只需在需要时翻到对应词条。

## 三、方法：双模型分工（记忆 vs 执行）

核心主张：**记忆由大模型精确记录，执行由 Qwen 高效完成**——这才是多 agent 在单机器人上的合理优势。

- **大模型（云端）= 记忆的"作者"**
  - 信息捕获强、记忆构建科学；
  - 在**探索 / 近距 / 交互时刻**精确记录语义信息（区域类型、物体、空间-时间、置信度）；
  - 不参与连续控制、不做实时仲裁。
- **小模型 Qwen3-VL-8B（本地）= 任务的"执行者"**
  - 基于语义拓扑**高效导航**、低延迟执行；
  - 本地构建 / 更新轻量信息灵活。
- **分工原则**：按**任务阶段与职责**划分，而非按置信度仲裁或共同决策。这从根上避免了"逻辑冲突"与"模型不自知错误"两个问题。

### Spatial Token Graph (STG)：双层空间记忆

- **上层 · 语义拓扑层**：区域连通关系（A-B-C-D-E）、方向、可通行性。→ 供小模型快速导航。
- **下层 · JSON 结构化语义层（"词典条目"）**：每个区域的物体信息 / 空间-时间信息 / 置信度。→ 供近距精查。

目标：提高信息**录用率**与记忆增强能力——拓扑负责"去哪"，词典负责"到了之后看什么"。

## 四、与相关工作的关系

- **Embodied-RAG**（树状语义、自底向上构建 + 自顶向下检索）：借鉴"语义记忆 + 检索生成"思想，但**反对全局地图式利用**，改为拓扑优先 + 局部词典式按需检索（见第二节）。
- **SkillOpt**（用 Skill 限制模型外部状态 + 带评分的轨迹优化）：借用 **Skill 约束**来规范小模型行为、防幻觉；轨迹评分是否纳入训练待定。
- **Mem2Ego**（多视角 RGB-D 拼接 + 多套记忆系统融合）：借鉴其**记忆构建 / 多视角融合**思路，用于大模型的精确记录环节。

## 五、室内任务实例

室内场景由空间 A-B-C-D-E 组成，小车需从 A 前往 C 的桌子旁取东西。

- A-B-C 依次相连。**对本次任务而言，只有拓扑信息有用**，其余全局信息都是冗余。
  → 小模型只取语义拓扑，自己通过 MCP 操控小车到达 C 即可。
- **到达 C 后**，再翻出此前大模型记录的"C 的具体物体信息"，接近并与目标物体交互。

这正是"远 → 拓扑（小模型）/ 近 → 语义（大模型记录的词典条目）"的落地。

## 六、架构思路（MCP-ROS Agent）

- **大模型记录语义 / 小模型执行任务**；接口形态：FunctionCall + MCP server + Memory。
- **底层保障**：
  - 安全：防碰撞 / 防死区 / 传感器健康；
  - Skill 切换：约束行为、防幻觉；
  - 硬件基础。
- **调度机制（Supervisor）**：负责 Skill 调度与异常处理。**实现方式待定**——可能是确定性代码，也可能下沉为一个小模型；下一轮专门讨论。
